# v1.1.0 Authentication, Users and Permissions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement stages 3–8 of Estoque Multiloja API v1.1.0: users, password hashing, JWT login, current-user resolution, admin/operator permissions, first-admin bootstrap and store-scoped endpoint protection.

**Architecture:** Keep the existing FastAPI + SQLAlchemy + Pydantic layers. Add `Usuario` to model/schema/CRUD/routes, place password/JWT code in `app/core/security.py`, and centralize authorization in `app/api/dependencies/auth.py`. Use HTTP Bearer so Swagger exposes **Authorize** while `/auth/login` accepts JSON `email` + `senha`.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy 2, Pydantic 2, Alembic, bcrypt, PyJWT, pytest.

**Spec:** `docs/superpowers/specs/2026-09-13-v1.1.0-design.md`

## Global Constraints

- JWT access token lifetime: 60 minutes.
- No refresh token in v1.1.0.
- Password minimum: 8 characters; never store plaintext.
- JWT secret comes from environment configuration and is never committed.
- Only admins create users through the API.
- Users are deactivated, not deleted.
- Admin may have `loja_id=None`; operator must have a valid `loja_id`.
- Operator can read/move stock only for their own store.
- Authentication failures return 401; permission failures return 403.
- Existing 16 behaviors remain covered after authentication is introduced.
- In the public demo, POST /auth/login is the only POST exempt from DEMO_READ_ONLY=true; all data-changing operations remain blocked.

- [ ] **Step 3: Implement bcrypt helpers**

```python
import bcrypt

def hash_password(password: str) -> str:
    return bcrypt.hashpw(password.encode("utf-8"), bcrypt.gensalt()).decode("utf-8")

def verify_password(password: str, password_hash: str) -> bool:
    try:
        return bcrypt.checkpw(password.encode("utf-8"), password_hash.encode("utf-8"))
    except ValueError:
        return False
```

## Stages 3–8 Completion Gate

Stages 3–8 are complete only when:

- Usuario model/table and Alembic migration are valid.
- Passwords are bcrypt-hashed.
- `/auth/login` issues a 60-minute JWT.
- Swagger shows Bearer **Authorize**.
- Missing/invalid/expired tokens return 401.
- Inactive users cannot authenticate.
- Admin/operator permissions return correct 403s.
- Operator access is limited to their store.
- First admin can be bootstrapped by script.
- Legacy behavior remains covered with authenticated requests.
- Full local pytest suite is green.
- `git diff --check` is clean.
- Branch remains `release/v1.1.0`.

After this gate, create the separate implementation plan for stages 9–11 (minimum stock, low-stock query and filters), then complete stages 12–14 (regression, docs/version, release/deploy).
